# Задача 4. Защита товарных остатков

## Проблема

Если остался один товар, два пользователя могут одновременно увидеть остаток `1` и попытаться купить его.

## Для чего это нужно

Количество проданных товаров никогда не должно превышать фактический остаток.

## Варианты решения

1. Пессимистическая блокировка `PESSIMISTIC_WRITE`.
2. Оптимистическая блокировка через `@Version`.
3. Атомарный `UPDATE` с проверкой остатка.

Для проекта удобно начать с атомарного обновления:

```sql
UPDATE products
SET quantity = quantity - :requested
WHERE id = :productId
  AND active = TRUE
  AND quantity >= :requested;
```

Если обновлено `0` строк, выбросить `InsufficientStockException` или `ProductUnavailableException`.

## Что изменить

- Добавить атомарный метод уменьшения остатка в `ProductRepository`.
- Вызывать его внутри `@Transactional` при подтверждении заказа или оплате.
- Не уменьшать остаток при простом добавлении в корзину.
- Добавить интеграционный тест с двумя параллельными покупками последнего товара.

Если товар должен резервироваться до оплаты, позднее создать `stock_reservations` со временем истечения резерва.
